# Нагрузочное тестирование

Модульные и интеграционные тесты отвечают на вопрос «правильно ли работает
сервис». Нагрузочные — на вопрос «выдержит ли он реальное число пользователей
и на чём именно сломается первым».

## Установка

```bash
pip install locust==2.32.4
```

## Подготовка

Нагрузочный тест бессмысленно гонять по пустой базе: запросы будут отдавать 404
и мерить скорость обработки ошибки, а не работу с данными.

```bash
make up && make backfill DAYS=365 && make train && make forecast
```

## Прогон

С веб-интерфейсом (открывается на http://localhost:8089):

```bash
locust -f loadtest/locustfile.py --host http://localhost:8000
```

Без интерфейса, с отчётом в HTML и кодом возврата для конвейера:

```bash
locust -f loadtest/locustfile.py --host http://localhost:8000 --headless --users 100 --spawn-rate 10 --run-time 2m --html loadtest/report.html
```

## Профиль нагрузки

Три класса пользователей имитируют разные источники трафика:

| Класс | Кого изображает | Пауза между действиями |
|---|---|---|
| `DashboardUser` | Студент, открывший дашборд | 1–5 с |
| `BotUser` | Telegram-бот: команды и рассылки | 2–8 с |
| `AdminUser` | Администрация, выгружающая CSV | 30–90 с |

Веса задач внутри классов подобраны под реальное распределение: текущее
состояние запрашивают в разы чаще, чем историю, а выгрузку отчёта — на порядки
реже. Равномерное распределение по эндпоинтам мерило бы не ту нагрузку,
которая будет в жизни.

## Проверяемые пороги

Тест завершается с ненулевым кодом возврата, если нарушено хотя бы одно
условие:

| Порог | Значение | Откуда взят |
|---|---|---|
| Доля ошибок | не более 1 % | общее требование к доступности |
| Медиана ответа `/api/current` | не более 300 мс | нефункциональное требование Н2 |

## Что смотреть в результатах

1. **Влияние кэша.** Прогоните тест дважды: с `CACHE_ENABLED=true` и с
   `CACHE_ENABLED=false`. Разница во времени ответа `/api/current` — прямая
   мера пользы от Redis, и это хороший материал для отчёта.
2. **Самый тяжёлый запрос.** Ожидаемо это `/api/history` за месяц и выгрузка
   CSV. Если они деградируют раньше остальных — узкое место в базе, а не в
   приложении.
3. **Момент отказа.** Постепенно поднимайте число пользователей, пока доля
   ошибок не превысит 1 %. Это и есть предел текущей конфигурации; цифру
   стоит привести в отчёте вместе с характеристиками машины.

## Ограничение

Прогон на той же машине, где работает сервис, меряет систему вместе с самим
нагрузчиком: Locust тоже потребляет процессор. Для честных цифр запускать его
следует с отдельной машины, а полученные значения трактовать как нижнюю
оценку производительности.
