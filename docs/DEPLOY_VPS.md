# Развёртывание на собственном сервере (Oracle Cloud Always Free)

Инструкция для случая, когда проект разворачивается не на сервере КБТУ, а на
своей виртуальной машине, в корне собственного домена. Вариант для сервера
университета — [DEPLOY.md](DEPLOY.md), он остаётся в силе.

Проверено: образ backend собирается и работает под `linux/arm64`, LightGBM
внутри контейнера запускается и обучает модель. Процессоры Ampere, которые
Oracle раздаёт бесплатно, — именно ARM, так что пересобирать ничего не нужно.

---

## 1. Что даёт Always Free

| Ресурс | Лимит бесплатного уровня |
|---|---|
| Процессор и память | 4 ядра Ampere A1 и 24 ГБ оперативной памяти суммарно |
| Диск | 200 ГБ блочного хранилища суммарно |
| Исходящий трафик | 10 ТБ в месяц |
| Срок | Бессрочно, пока аккаунт остаётся на бесплатном уровне |

Проекту с запасом хватает **2 ядер и 12 ГБ** — это половина лимита. Обучение
модели на 417 тысячах строк требует около 2 ГБ, всё остальное уходит на
PostgreSQL и контейнеры.

Условия у Oracle меняются, поэтому актуальные лимиты стоит сверить на их
странице Always Free — цифры выше приведены по состоянию на момент написания.

---

## 2. Регистрация и как не начать платить

**Карта нужна.** При регистрации Oracle требует банковскую карту для
подтверждения личности и делает временную блокировку небольшой суммы (обычно
около доллара), которая затем снимается. Это проверка, а не оплата. Введите
данные карты сами — никому их не передавайте.

Три правила, которые гарантируют нулевой счёт:

1. **Никогда не нажимайте «Upgrade to Pay As You Go».** Пока аккаунт на
   бесплатном уровне, Oracle физически не даст создать платный ресурс: попытка
   выйти за лимит завершится отказом, а не списанием.
2. **Создавайте ресурсы только с пометкой «Always Free eligible».** В
   интерфейсе она стоит прямо у формы выбора.
3. **Не превышайте суммарные лимиты** из таблицы выше. Например, две машины по
   2 ядра допустимы, три по 2 — уже нет.

**Отдельно про простой.** Oracle оставляет за собой право освобождать
бесплатные вычислительные ресурсы, которые долго простаивают без нагрузки.
Наш проект нагружает машину раз в час и ночью при переобучении, что немного,
поэтому риск есть. Точные критерии описаны в документации Oracle; если машина
важна, за этим стоит следить и хотя бы иногда заходить на дашборд.

## 3. Создание виртуальной машины

Compute → Instances → Create instance.

| Параметр | Значение |
|---|---|
| Image | Ubuntu 24.04 (или 22.04) |
| Shape | Ampere A1 Flex, **2 OCPU, 12 GB** |
| Boot volume | 50–100 ГБ |
| SSH keys | Загрузить свой публичный ключ или дать Oracle сгенерировать пару |

Приватный ключ, если генерировали в браузере, скачивается **один раз** —
потеряете, доступ к машине пропадёт.

**«Out of capacity».** Самая частая проблема с бесплатными ARM-машинами:
Oracle отвечает, что в регионе нет свободных мощностей. Что помогает:

- пробовать другую зону доступности внутри региона;
- пробовать в другое время суток, спрос неравномерен;
- взять меньше ядер: 1 OCPU и 6 ГБ выделяются заметно чаще, проекту этого
  хватит, если отключить ночное переобучение (см. раздел 9).

Регион аккаунта выбирается один раз при регистрации и потом не меняется, так
что при регистрации имеет смысл выбрать не самый загруженный.

## 4. Открыть порты — здесь застревают чаще всего

Порты нужно открыть **в двух местах**. Если сделать только одно, сервер будет
молчать, и причина будет неочевидна.

**Первое: облачный фаервол.** Networking → Virtual Cloud Networks → ваша VCN →
Security Lists → Default Security List → Add Ingress Rules. Добавить два
правила: Source `0.0.0.0/0`, протокол TCP, порт назначения `80`, и такое же
для `443`.

**Второе: фаервол внутри машины.** Образы Ubuntu от Oracle приходят с уже
настроенными правилами iptables, где всё, кроме SSH, отклоняется. Подключиться
по SSH и посмотреть:

```bash
sudo iptables -L INPUT --line-numbers
```

В конце списка будет правило `REJECT`. Новые разрешения нужно вставить **до**
него — подставьте свой номер строки вместо `6`:

```bash
sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 80 -j ACCEPT
sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 443 -j ACCEPT
sudo netfilter-persistent save
```

Без `netfilter-persistent save` правила исчезнут после перезагрузки.

## 5. Домен

Для HTTPS нужно доменное имя: сертификат на голый IP-адрес не выпускается.

- **Бесплатно и сразу:** DuckDNS — регистрация через GitHub, выдаёт имя вида
  `myproject.duckdns.org` и позволяет указать IP.
- **Свой домен на год:** входит в GitHub Student Developer Pack (Namecheap).

Что бы ни выбрали, создайте **A-запись** с именем домена на публичный IP
машины и дождитесь, пока она разойдётся:

```bash
dig +short air.example.com
```

Команда должна вернуть IP вашей машины. **Это надо сделать до первого
запуска:** Caddy выпускает сертификат при старте и, если домен ещё не
указывает на сервер, получит отказ.

## 6. Установка Docker

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
```

Выйти из SSH и зайти заново, иначе группа не применится. Проверка:

```bash
docker run --rm hello-world
```

## 7. Развёртывание

```bash
git clone https://github.com/Fixsbreaker/Air-Quality-Kampus.git
cd Air-Quality-Kampus
cp .env.vps.example .env
```

Заполнить `.env`. Сгенерировать два секрета:

```bash
openssl rand -hex 32    # POSTGRES_PASSWORD, тот же пароль вписать в DATABASE_URL
openssl rand -hex 32    # ADMIN_TOKEN
```

И указать `DOMAIN`, `ACME_EMAIL` и `CORS_ORIGINS` — везде свой домен.

Запуск:

```bash
docker compose -f docker-compose.vps.yml --env-file .env up -d --build
```

Первая сборка на 2 ядрах занимает 5–10 минут: собираются образы backend и
фронтенда. Дальше Caddy сам получит сертификат — это ещё несколько секунд.

Проверка:

```bash
docker compose -f docker-compose.vps.yml ps
docker compose -f docker-compose.vps.yml logs aqi-caddy | tail -20
curl -I https://ваш-домен
```

## 8. Наполнение данными

После первого запуска база пуста, и дашборд честно скажет, что данных нет.
Нужно один раз выкачать архив и обучить модель:

```bash
docker compose -f docker-compose.vps.yml exec aqi-api python -m scripts.backfill --days 730
docker compose -f docker-compose.vps.yml exec aqi-api python -m scripts.train
docker compose -f docker-compose.vps.yml exec aqi-api python -m scripts.make_forecast
```

Дальше всё поддерживается само: сбор данных каждый час, пересчёт прогноза
каждый час, переобучение в 03:00 — этим занимается контейнер `aqi-worker`.

## 9. Если досталась машина на 1 ядро и 6 ГБ

Проект будет работать, но ночное переобучение может не поместиться в память.
Решение: обучать модель не на сервере, а локально, и переносить готовый
артефакт.

Отключить переобучение — убрать расписание в `.env`:

```
RETRAIN_CRON_HOUR=
```

Затем скопировать обученную модель с локальной машины в том сервера:

```bash
docker compose exec -T aqi-api tar -C /app/models -cf - . | \
  ssh ubuntu@ВАШ_IP 'docker exec -i aqi_api tar -C /app/models -xf -'
```

Сбор данных и расчёт прогноза при этом продолжат работать: они лёгкие.

## 10. Обновление

```bash
git pull
docker compose -f docker-compose.vps.yml up -d --build
```

База, модель и сертификаты лежат в именованных томах и пересборку переживают.
`down` без флага `-v` их тоже не трогает.

## 11. Диагностика

| Симптом | Что смотреть |
|---|---|
| Сайт не открывается совсем | Порты: оба места из раздела 4. Проверить `curl -I http://IP` — если молчит, дело в фаерволе |
| Caddy не выпускает сертификат | `dig +short домен` должен вернуть IP машины; порт 80 должен быть открыт — он нужен для проверки владения |
| `502 Bad Gateway` | Не поднялся `aqi-web` или `aqi-api`: `docker compose -f docker-compose.vps.yml logs aqi-api` |
| Страница открылась, данных нет | Не выполнен `backfill` — раздел 8 |
| График прогноза пуст | Не выполнены `train` и `make_forecast` |
| Данные не обновляются | `docker compose -f docker-compose.vps.yml logs aqi-worker` |
| Машина исчезла | Возможно, освобождена как простаивающая — см. раздел 2 |

Общее состояние, включая доступность базы и активную версию модели, отдаёт
`https://ваш-домен/health`.

## 12. Чек-лист «я точно ничего не плачу»

- [ ] В шапке консоли Oracle написано **Always Free**, а не Pay As You Go
- [ ] Создана одна машина, суммарно не более 4 ядер Ampere и 24 ГБ
- [ ] Форма создания показывала пометку «Always Free eligible»
- [ ] Не создавались платные сервисы: балансировщики, управляемые базы, резервные копии
- [ ] В разделе Billing → Cost Analysis сумма нулевая
