# Проверка источников данных (Шаг 0)

Техническое задание требует до написания кода убедиться, что источник отдаёт данные:
«если данных нет — проекта нет». Ниже зафиксирован результат проверки.

## Итог

| Источник | Что проверяли | Ответ | Решение |
|---|---|---|---|
| Open-Meteo Air Quality — текущие и прогноз | `GET /v1/air-quality` с `past_days=2&forecast_days=2` | **200 OK**, часовой ряд PM2.5, PM10, NO₂, O₃ | Основной источник |
| Open-Meteo Air Quality — архив | тот же эндпоинт с `start_date` / `end_date` за 2024 год | **200 OK**, данные есть | Источник обучающей выборки |
| Open-Meteo Archive — погода | `GET /v1/archive` за произвольный период | **200 OK**, температура, ветер, влажность, давление | Погодные признаки модели |
| Airkaz.org | `GET https://airkaz.org/map_data.php` | **404 Not Found** | Отключён, реализован как необязательный |

## Команды проверки

Качество воздуха, текущие значения и прогноз:

```bash
curl -s "https://air-quality-api.open-meteo.com/v1/air-quality?latitude=43.2364&longitude=76.9457&hourly=pm2_5,pm10,nitrogen_dioxide,ozone&past_days=2&forecast_days=2&timezone=UTC" | head -c 600
```

Исторический архив качества воздуха:

```bash
curl -s "https://air-quality-api.open-meteo.com/v1/air-quality?latitude=43.2364&longitude=76.9457&hourly=pm2_5,pm10&start_date=2024-08-01&end_date=2024-08-03&timezone=UTC" | head -c 400
```

Архив погоды:

```bash
curl -s "https://archive-api.open-meteo.com/v1/archive?latitude=43.2364&longitude=76.9457&hourly=temperature_2m,wind_speed_10m&start_date=2024-08-01&end_date=2024-08-02&timezone=UTC" | head -c 400
```

Airkaz:

```bash
curl -s -o /dev/null -w "HTTP %{http_code}\n" "https://airkaz.org/map_data.php"
```

## Что важно в ответе Open-Meteo

1. **Ключ не нужен.** API бесплатный для некоммерческого использования, ограничение —
   примерно 10 000 запросов в сутки. Проект делает 6 запросов в час (3 точки × 2
   эндпоинта), то есть 144 в сутки — с большим запасом.

2. **Ответ приходит «колонками», а не списком объектов.** Структура такая:

   ```json
   {
     "hourly": {
       "time":  ["2026-08-07T00:00", "2026-08-07T01:00"],
       "pm2_5": [12.4, 18.9],
       "pm10":  [25.0, 33.1]
     }
   }
   ```

   Массивы выровнены по индексу, поэтому разбор идёт по позиции. Если какой-то
   переменной в ответе нет, колонка просто отсутствует — клиент подставляет `None`.

3. **Пропуски приходят как `null`**, а не как ноль. Это важно: ноль означал бы
   «чистый воздух», а `null` — «данных нет». Клиент сохраняет различие.

4. **В ответе есть будущее.** Эндпоинт вместе с фактическими значениями отдаёт
   собственный прогноз источника на двое суток вперёд. Строки сохраняются в базу
   (позже перезаписываются фактом), но при обучении и построении признаков всё
   позже текущего момента отсекается — иначе модель приняла бы чужой прогноз за
   наблюдение.

5. **Часовой пояс.** Все запросы делаются с `timezone=UTC`, время хранится в базе
   в UTC без смещения. Перевод в Asia/Almaty (UTC+5) делается только при выдаче.

6. **Данные приходят с расчётной сетки, а не с датчиков** — см. следующий раздел.

## Ограничение пространственного разрешения

Open-Meteo не измеряет воздух, а отдаёт результат расчётной модели, привязанный к
регулярной сетке. Координаты запроса «прищёлкиваются» к ближайшему узлу, и в ответе
возвращаются координаты именно узла, а не запрошенной точки. Проверка:

Координаты объектов КБТУ получены геокодированием официальных адресов через
OpenStreetMap (Nominatim); объект на Тургут Озала подписан в OSM как «Общежитие КБТУ».

| Объект | Координаты | Узел сетки | PM2.5 |
|---|---|---|---|
| Учебный корпус, Толе би 59 | 43.25573, 76.94313 | 43.30, 76.90 | 16.1 |
| Общежитие, Тургут Озала 80 | 43.25219, 76.88085 | 43.30, 76.90 | 16.1 |
| Общежития, Ислама Каримова 70 | 43.23704, 76.88516 | 43.20, 76.90 | 16.1 |
| Контроль: Медеуский район | 43.20000, 77.00000 | 43.20, **77.00** | **8.5** |

Решающая проверка — сравнение не одного часа, а месячных рядов (январь, 744 часа):

| Пара точек | Средние за январь | Ряды совпадают |
|---|---|---|
| Толе би 59 и Тургут Озала 80 | 34.46 и 34.46 | **да, полностью** |
| Толе би 59 и Ислама Каримова 70 | 34.46 и 34.46 | **да, полностью** — хотя узлы сетки разные |

Шаг сетки — 0.1°, то есть около 11 км по широте и 8 км по долготе на широте Алматы.

Шаг сетки 0.1° — около 11 км по широте и 8 км по долготе на широте Алматы. Но
формальная принадлежность к разным узлам ещё не гарантирует разных значений: учебный
корпус и общежитие на Ислама Каримова попали в разные узлы, а ряды у них совпали
полностью. Расчётная модель источника для западной части Алматы фактически однородна.

**Все объекты КБТУ расположены на западе города, и источник не различает их в
принципе.** Различие появляется только при переходе через долготу 77° — в Медеуском
районе у предгорий концентрация примерно вдвое ниже (8.5 против 16.1 мкг/м³).

Практические следствия:

1. **Разбивка по объектам КБТУ при этом источнике не несёт информации.** Дашборд
   проговаривает это явно, а не показывает три одинаковых числа молча.
2. Обучать модель на трёх копиях одного ряда бессмысленно, поэтому дублирующие ряды
   отсеиваются в `build_dataset` по хешу. Выборка сократилась с 1 252 356 до 417 246
   строк, а MAE изменилась в третьем знаке — 7.766 против 7.776. Практический вывод:
   объём выборки сам по себе ничего не даёт, значение имеет разнообразие.
3. Список объектов и многоточечная архитектура сохранены намеренно: схема базы, API
   и интерфейс уже готовы принимать данные из разных источников. Как только появятся
   наземные датчики, разделение заработает без переделки кода.
4. Ограничение сетки — главный аргумент в пользу установки собственных датчиков:
   разницу между выходом на проспект и внутренним двором модельная сетка не покажет
   ни при каких координатах.

Воспроизвести проверку:

```bash
curl -s "https://air-quality-api.open-meteo.com/v1/air-quality?latitude=43.2364&longitude=76.9457&hourly=pm2_5&forecast_days=1&timezone=UTC" | head -c 200
```

## Почему Airkaz оставлен в коде

Технического задание прямо предусматривает этот риск: «Airkaz не отдаёт данные →
Open-Meteo как основной источник, Airkaz — приятный бонус». Адаптер написан и покрыт
тестами, но выключен флагом `AIRKAZ_ENABLED=false`:

- при любой сетевой или разборной ошибке возвращает пустой список и пишет
  предупреждение в лог;
- сбор данных по Open-Meteo продолжается независимо;
- если сеть снова откроет публичный эндпоинт, источник включается одной переменной
  окружения, без правки кода.

Разбор ответа сознательно сделан «терпимым»: формат Airkaz исторически менялся,
поэтому неизвестные и пустые поля пропускаются, а станции фильтруются по расстоянию
до точки кампуса (формула гаверсинуса, радиус по умолчанию 3 км).
